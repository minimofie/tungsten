# UI framework

Tungsten's UI parts are **components**: List, Dropdown, TypePicker, ContextMenu, CellEditor, ColorPicker, SequenceEditor, ConfirmBar, Prompt, Notify, Tooltip, CommandBar, Input, Button, Toggle, Label, TextEditor, Scroll, Page (layout pieces for a tab) and SubTabs (views inside one tab). Each one registers with the UI framework. A plugin uses the framework to:

- **make** components by name, looking exactly like Tungsten's own;
- **listen** to their events (a selection changed, an option was picked, a menu closed);
- **filter** the data they show (which options a dropdown lists, which items a menu draws, the text in a list cell).

The look is never a plugin's to change: filters adjust data, events report what happened. `/ui` lists the components; `/ui List` lists one component's events and filters, and which plugins use them.

> In a plugin, use its `api` (`api.ui`, `api.menus`, `api.prompt`, `api.notify`, `api.docs`, … see **Plugins › The api**): it sets `Origin` and `Owner` for you, and everything goes when the plugin stops. The examples on this page call Tungsten's modules directly and pass the owner by hand, as console code would.

Right-click and button menus have their own framework on top of this one: see **Menus**.

## Making components

```
local UI = tungsten.UI
local list = UI.new("List", {
	Parent = page, Origin = "myplugin",
	Columns = { { Key = "Name", Flex = true }, { Key = "Class", Type = "class", Editable = true } },
	Menu = "myplugin.items",
})
local pick = UI.new("TypePicker", { Parent = row, Kind = "isa:BasePart", Origin = "myplugin" })
```

`Origin` says who made the component. Plugins get their own id, and Tungsten's components are `core`.

## Scale

**Window size** makes the window bigger or smaller, like resizing it; nothing inside is zoomed. Lay pages out so they stretch (scale parts of `UDim2`, lists, panes) and they use the extra room on their own; fixed sizes stay fixed. Text widths from `Create.textWidth` are pixels.

Contents are drawn 1:1, so screen pixels and layout pixels are the same today. The helpers below still do the conversion, so code that uses them keeps working if that ever changes:

| Helper | Gives |
|---|---|
| `Create.layoutSize(frame)` | the frame's size in layout pixels |
| `Create.toLocal(point, frame)` | a screen point as an offset from the frame's top-left corner |
| `Create.scaleOf(frame)` | how big the frame is drawn (1 = 100%) |

Popups opened through `Overlay.place` / `Overlay.open` take on-screen anchors (a button's `AbsolutePosition` and `AbsoluteSize`) and handle the rest. (`Create` is `tungsten.import("base/ui/create")`.)

## Filters

A filter gets the value and returns a new one. Return nothing to keep the value. A value of a different type is ignored and a warning goes to the log.

```
-- every class picker of this plugin also offers "Vehicle"
UI.filter("TypePicker", "Options", function(options, kind)
	if kind == "class" then
		table.insert(options, { Value = "Vehicle", Text = "Vehicle", Icon = "class_model" })
	end
	return options
end, { Owner = "myplugin" })
```

| Component | Filter | Gets |
|---|---|---|
| List | Items | the rows a list shows |
| List | CellText | the text of one cell (column, item) |
| List | EditMenuItems | the "Edit …" entries a list adds to menus |
| Dropdown | Options | the options an option list shows |
| Dropdown | Search | the matches for typed search text |
| TypePicker | Options | the options of any kind, built-in ones too |
| ContextMenu | Items | the items a menu is about to draw |
| CellEditor | Text | the text the box starts with |
| Prompt | Options, Fields | the choices of a choice dialog, the fields of a form |
| Notify | Toast | the options of a toast about to show |
| Tooltip | Text | the text about to show |
| CommandBar | Input | the input about to run |

## Scope

A hook or filter has a **Scope**:

- `"own"` (the default for plugins): only components with the same `Origin`, so a plugin's hooks never touch Tungsten's own windows or other plugins'.
- `"all"`: every component, Tungsten's included. Use it for things like recording which menu items get used, never to change how something looks.

`{ Order = 10 }` makes a hook run before others (lower first).

## Picker kinds, value types and classes

Type selectors read their lists from registries that plugins can add to:

| Call | Adds |
|---|---|
| `TypePicker.registerKind("team", { Options = function(arg) … end })` | a new picker kind (`Type = "team"` in a list column, `Kind = "team"` for a picker) |
| `tungsten.Types.registerType("Money", { Is, Parse, EditText, Display, Default, Hint, Icon, Color })` | a value type: shown in type pickers, parsed and edited in list cells and the cell editor, used by `/setas` and `/cast` |
| `Classes.add("Vehicle", "vehicle", { Creatable = false })` | a class with its category's icon, offered by class pickers |
| `Categories.addClassCategory("vehicle", { Icon, Color, Title })` | a class category (icon, tint, title) |

`Is(value)` decides which values belong to a type. `Parse(text)` returns `true, value` or `false, reason`, and the reason is shown under the cell editor.

## Property editors

The properties panel asks an **editor** how to show and change each value. Editors are registered by value type, or for one property of a class (subclasses share it):

```
local Editors = tungsten.Editors
Editors.register("BasePart.Transparency", {
	Inline = "dropdown",          -- "text", "toggle", "dropdown", "swatch" or "popup"
	Options = function(ctx) return { { Value = 0, Text = "Solid" }, { Value = 1, Text = "Invisible" } } end,
	Display = function(value) return if value == 1 then "Invisible" else tostring(value) end,
	Owner = "myplugin",
})
```

| Field | Use |
|---|---|
| `Inline` | what the value cell shows: text, a switch, a list, a color square, or text with a ⋯ button |
| `Display(value, prop)` | the cell's text |
| `Swatch(value)` | the color square's Color3 |
| `Options(ctx)` | items for `dropdown` |
| `Open(ctx)` | a popup editor (the square / ⋯ button); call `ctx.Apply(newValue)` to set it on every selected object |
| `Fields` | parts shown under the row: `{ Name, Type, Get(value), Set(value, part) }` |
| `Parse(text, prop)` / `EditText(value, prop)` | text editing |

`ctx` has `Prop`, `Value`, `Same`, `Instances`, `AnchorPos`, `AnchorSize` and `Apply`. A plugin's editor sits on top of Tungsten's own; removing the plugin brings Tungsten's back. ColorPicker and SequenceEditor can be opened by plugins too (`UI.new("ColorPicker", { AnchorPos = …, Value = color, OnChange = fn })`).

Popups that edit a value end with **Cancel** and **Accept** (the ConfirmBar component). They share one rule: changes reach `OnChange` as they are made (a live preview); **Accept** keeps them and calls `OnAccept(value)`; **Cancel** or **Escape** sends the original value to `OnChange` again (only if something changed) and calls `OnCancel(original)`; a click outside keeps the change, like Accept. Pass `Live = false` to get `OnChange` only on Accept. `AcceptText` / `CancelText` change the button labels. The palette takes `PickCloses = true` to pick with one click and close. A popup of your own can use the same buttons: `UI.new("ConfirmBar", { Parent = frame, Position = …, OnAccept = fn, OnCancel = fn })`, with `ConfirmBar.closeMeans(reason)` telling an overlay close reason apart (`"accept"` or `"cancel"`).

The explorer's **Insert ›** menu can be shaped too: `Explorer.Insert.addGroup({ Id = "vehicles", Title = "Vehicles", Classes = { "VehicleSeat", "Seat" }, Order = 25 }, "myplugin")` adds a group (or give `Test = function(className) return … end`), `Explorer.Insert.setCommon({ … })` replaces the Common list, and `Classes.add("MyClass", "part", { Creatable = true })` adds a class. `Explorer.insert(className, parents)` and `Explorer.moveInto(objects, target)` do what the menu and dragging do, and `Explorer.Moved` / `Explorer.Insert.Inserted` fire afterwards.

## Dialogs, toasts and tooltips

```
local Prompt, Notify = tungsten.Prompt, tungsten.Notify
if Prompt.await(Prompt.confirm({ Title = "Delete 3 objects?", Danger = true, ConfirmText = "Delete" })) then … end
local count = Prompt.await(Prompt.input({ Title = "How many?", Type = "number" }))
local team = Prompt.await(Prompt.choice({ Title = "Team", Options = { "Red", "Blue" } }))
local values = Prompt.await(Prompt.form({ Title = "New rule", Fields = {
	{ Key = "name", Label = "Name", Kind = "text", Required = true },
	{ Key = "mode", Label = "Mode", Kind = "dropdown", Options = { "Log", "Block" } },
	{ Key = "class", Label = "Class", Kind = "isa:BasePart" },       -- any picker kind
	{ Key = "where", Label = "Where", Kind = "value", ValueType = "Vector3" },
} }))
Notify.success("Saved 3 objects", "Saved")
Notify.show({ Text = "Remote fired", Kind = "warn", Actions = { { Text = "Open", Callback = fn } } })
tungsten.UI.new("Tooltip", { Target = button, Text = "What this does" })
```

| Kind | Returns (with `Prompt.await`) |
|---|---|
| `Prompt.confirm` | true, or false when cancelled |
| `Prompt.input` | the value (parsed as `Type`), or nil |
| `Prompt.choice` | the picked value (a list with `Multi = true`), or nil |
| `Prompt.form` | `{ [Key] = value }`, or nil |
| `Prompt.custom` | `Build(body, handle)` fills the card; `Buttons` of your own |
| `Prompt.popover` | a panel next to something; a click outside closes it |

Dialogs open inside the main window, centred on it, with an accent outline; nothing is darkened. Clicks outside the card do nothing and Escape cancels. Pass `Dim = true` to darken the window behind a dialog, or `Screen = true` to centre it on the whole screen instead. Every kind takes `Title`, `Text`, `Icon`, `Width` and extra `Buttons`. Field kinds: `text`, `number`, `toggle`, `dropdown`, `value`, `label`, any picker kind, and your own with `Prompt.registerFieldKind("color", { Build = function(holder, field, form) return { Get = …, Set = … } end })`. Toast kinds: `info`, `success`, `warn`, `error`, and your own with `Notify.registerKind`.

## Searching

Every text search (dropdown and picker lists, the documentation, the explorer's filter boxes) takes the same words: several words must all match, `!word` must not, `"Exact"` must be exact, and `hint:Part` / `group:Explorer` look at a field. A dropdown of your own can bring its own rule with `Match = function(option, text) return … end`.

## Tabs and icons

```
tungsten.Icons.register("myplugin.gear", "Tungsten/plugins/MyPlugin/gear.png", { Owner = "myplugin" })
tungsten.Registry.addTab({
	Id = "myplugin", Title = "My Plugin", Icon = "myplugin.gear", Owner = "myplugin",
	Tooltip = "What it does", Badge = 3,
	Build = function(page, T, tab) end,
	OnSelect = function(tab) end, OnDeselect = function(tab) end,
	OnLoad = function(values, tab, items) end,          -- every load (any tab open)
	MenuItems = function(ctx) return { { Text = "Reset", Callback = fn } } end,
})
tungsten.Registry.updateTab("myplugin", { Badge = 5, Title = "My Plugin (5)" })
```

A plugin gets its tab from `Tab` in its definition and keeps to that one tab: more views go in **sub-tabs** across its top (`api.ui.subtabs`, see **Plugins › Building its tab**). Sub-tabs look like the rest of Tungsten: rounded pills on a band under the path bar, the open one filled like the open side-bar tab, and a badge (`tabs:Badge(id, n)`, or `Badge` in a sub-tab's definition) like the side bar's. Sub-tabs that don't fit scroll sideways with the mouse wheel. `api.tab.select()`, `api.tab.badge(n)` and `api.tab.update{…}` change its own tab.

An icon is a file (loaded with `getcustomasset`), an `rbxassetid://` image, or a sprite `{ Image, RectOffset, RectSize }`; `Colored = true` keeps its own colors. Icons work everywhere icons do: tabs, menus, lists, pickers.

The side bar scrolls when the tabs don't fit. Hovering a tab shows its title; right-clicking it gives **Open**, **Move up / down**, **Hide tab** (plugin tabs), the tab's own entries and **Show hidden tabs**. **Ctrl+Up / Ctrl+Down** switch tabs. The order and hidden tabs are remembered.

## Documentation for plugins

```
local Docs = tungsten.Docs
Docs.addTopic({ Id = "myplugin", Title = "My Plugin", Group = "My Plugin", Source = "# My Plugin\n…", Owner = "myplugin" })
Docs.addTopic({ Id = "myplugin-live", Title = "Live view", Group = "My Plugin", Build = function(content, view) end, Owner = "myplugin" })
Docs.addSection("commands", { Title = "My Plugin", Source = "…", Owner = "myplugin" })
Docs.addDirective("myplugin-stats", { Source = function(arg) return "**" .. count .. "** calls" end, Owner = "myplugin" })
```

A topic is markdown (`Source`, or a `File`), or a page of your own UI (`Build`). A **section** adds to any topic, Tungsten's too. A **directive** is a live block: write `{{myplugin-stats}}` (or `{{myplugin-stats:arg}}`) in any topic and it is filled in each time the page shows. Plugin topics are listed after Tungsten's, with their group's name. Built-in directives: `{{commands:Group}}`, `{{commands-other}}`, `{{plugin-commands}}`, `{{menus}}`, `{{components}}`, `{{filter-groups}}`, `{{groups}}`.

## Printing to the console

Each plugin gets a **reporter**, its own console printer:

```
local out = tungsten.Console.reporter("myplugin", { Label = "My Plugin" })
out:info("loaded 12 items")            -- [plugin] My Plugin: loaded 12 items
out:success("saved")                   -- [plugin] My Plugin: saved
out:warn("3 items skipped")            -- [!] My Plugin: 3 items skipped
out:error("could not read the file", { Hints = { "check the file name" } })
out:value("result = ", workspace.Baseplate)
local ok, result = out:try(function() return risky() end)   -- a failure becomes an [x] line
button.Clicked:Connect(out:wrap(onClick, "Saving"))          -- "[x] My Plugin: Saving failed: …"
```

`error` makes an error record (kind `plugin`) with the hints, code and traceback you give it. `try` and `wrap` catch errors and report them with their traceback. A plugin's `api.console` (`print`, `success`, `warn`, `error`, `value`) and `api.console.reporter` are this reporter, made for it. A plugin doesn't need to report the faults Tungsten catches for it: a failing `Load` or `Unload`, commands and their completion, menu entries, explorer functions, its tab and sub-tabs, settings buttons, hooks, filters, picker kinds, custom rows and its owned connections and threads are reported under the plugin's name on their own, and counted on its page in the Plugins tab.

The explorer uses the same mechanism (`[+] Explorer: …`, `[x] Explorer: …`; `tungsten.Explorer.report("warn", "text")`).

## Cleanup

`UI.removeOwner("myplugin")` removes everything a plugin added: hooks, filters, menus and menu entries, row kinds, picker kinds, value types, classes, categories, property editors, filter groups, tabs, icons, form field kinds, toast kinds, documentation (topics, sections, directives, groups), commands, variables, undo steps, insert groups and its reporter. When a plugin stops, Tungsten calls its `Unload`, then `api:remove()`, which also ends its owned connections and threads and runs this.
